# 发匣 FaXia：写一次 Markdown，同时发布到 11 个平台

你花了一个周末写完一篇技术长文。代码跑过了，配图也做好了。然后呢？你打开 11 个浏览器标签页，每个平台复制粘贴一遍，调格式、传图片、改链接——折腾一小时，发现还漏了一个平台。

**这不是你的问题，是工具的问题。**

今天介绍的 **发匣 FaXia** 就是来解决这件事的。你只需要写一份 Markdown，它帮你并发发布到 GitHub Pages、微信公众号、知乎、掘金、头条、微博、Reddit、X/Twitter、Medium、Facebook、LinkedIn——全程自动。

## 它能做什么？

### 十一大平台，一键并发

支持的 11 个平台覆盖了国内外的核心内容渠道。有官方 API 的用 API（如 Medium、GitHub Pages），没有的就用 Playwright 模拟浏览器操作（如头条、微博），全自动完成。

你可以全部一起发，也可以用参数指定只发某几个平台。每个平台独立运行，一个失败不影响其他——真正做到了"一起发，互不影响"。

### 图片自动上传，告别外链挂图

Markdown 里插入的本地图片，发匣 FaXia 会自动上传到对应平台的图床，然后把文章里所有的图片链接替换成正确的线上地址。你的截图、架构图、代码对比图，在每个平台都能正常显示。

### 智能更新，不发重复帖

发布过的文章 发匣 FaXia 会记录下来。重新发布同一篇文章时，它会自动识别并更新已有帖子（支持的平台），而不是再发一篇新的。改错别字、补充内容、更新数据，轻松搞定。

### 命令行 + 桌面端，随意切换

- **桌面端（Electron）**：可视化的平台选择、凭证管理、实时预览，拖文件点按钮就发
- **CLI（`tdp`）**：支持脚本化、CI 集成，适合批量操作和自动化流程

两套界面共用一套发布引擎，选你顺手的用。

### Dry-Run：先演练，再上场

`tdp check` 一键检查所有平台的凭证是否有效。`--dry-run` 把整个发布流程走一遍但一条都不发。提前排查问题，杜绝发一半、错一半的尴尬。

## 怎么开始？

1. 下载对应系统的安装包，或直接 `npm install -g blog-assistant`
2. 配置平台凭证（桌面端有设置面板，支持 API Token / Cookie 两种方式）
3. 写 Markdown 文章（可选 YAML frontmatter 填标题、标签）
4. 一条命令发布：`tdp publish 文章.md`
5. 查看每个平台返回的成功状态和直达链接

**写文章的时间，应该用来写更多好文章——而不是当搬运工。**

发匣 FaXia 是纯本地工具：开源、无云端、无埋点，你的凭证和内容完全在自己手里。MIT 协议，自由使用。
